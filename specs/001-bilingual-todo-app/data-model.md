# Data Model: Bilingual Todo App

Two data owners: the **mock backend** owns `Todo`; **Contentful** owns everything else. Todos reference
Contentful items only by stable `slug`, never by translated name. Full Contentful field definitions are in
[contracts/content-model.md](contracts/content-model.md); the HTTP shape of `Todo` is in
[contracts/todos-api.openapi.yaml](contracts/todos-api.openapi.yaml).

## Todo (backend)

| Field | Type | Required | Rules |
|-------|------|----------|-------|
| id | string or number | yes | Generated by backend; immutable |
| title | string | yes | 1-120 characters after trimming; shown exactly as typed (FR-021) |
| description | string | no | 0-500 characters; shown exactly as typed |
| completed | boolean | yes | Default `false` |
| categorySlug | string | no | Should match a Category slug; may become orphaned (shown as Uncategorized) |
| prioritySlug | string | yes | One of Priority slugs (`low`, `medium`, `high`); default `medium` |
| dueDate | date (`YYYY-MM-DD`) | no | Past dates allowed (clarification Q3) |
| createdAt | date-time | yes | Set by backend on create; immutable |
| updatedAt | date-time | yes | Set by backend on every change |

**State**: `active` (completed = false) and `completed` (completed = true); toggled any number of times.
**Derived (client)**: `overdue` = not completed and `dueDate` earlier than today in the user's local date.
Today's date itself is not overdue.

## Contentful entities (read-only to the app)

All text fields are localized (`en-CA`, `fr-CA`); non-text fields are not.

### AppSettings (single entry)
`appTitle`*, `tagline`, `logo` (asset, not localized), `logoAlt` (L, required when `logo` is set), `footerText`, `languageSwitcherLabel`*

### UiLabel
`key`* (unique, not localized, e.g. `button.addTodo`), `value`* (localized), `group`* (Buttons, Forms, Validation, Messages, Filters, Navigation, Status)

### Category
`name`* (L), `slug`* (unique), `colour`* (hex), `icon`, `sortOrder`*
Initial: personal, work, shopping, health.

### Priority
`label`* (L), `slug`* (unique: low, medium, high), `level`* (integer, higher = more important), `colour`*

### Page
`title`* (L), `slug`* (unique: home, help), `intro` (rich text, L), `emptyState` (reference to EmptyState), `seoTitle` (L), `seoDescription` (L)

### EmptyState
`heading`* (L), `message`* (L), `illustration` (asset), `illustrationAlt` (L, required when `illustration` is set), `callToActionLabel` (L)

### FaqItem
`question`* (L), `answer`* (rich text, L), `sortOrder`*

`*` = required.

## Client-side models

| Model | Purpose |
|-------|---------|
| `LocalizedField<T>` | Map keyed by Contentful locale (`en-CA`, `fr-CA`) as delivered |
| `ResolvedText` | `{ text: string; lang: 'en-CA' \| 'fr-CA' }`, the result of fallback resolution; `lang` differs from the page language only on fallback |
| `ContentSnapshot` | All entries from the single content load, indexed: labels by key, categories and priorities by slug (sorted by `sortOrder`/`level`), pages by slug, FAQ sorted |
| `TodoFilterState` | `status: all \| active \| completed`, `categorySlug \| null`, `prioritySlug \| null`, `search: string`, `sortBy: dueDate \| priority \| createdAt`, `sortDirection` |
| `LoadStatus` | `idle \| loading \| ready \| error` for content and tasks separately |
| `LanguagePreference` | `{ urlLang: 'en' \| 'fr'; locale: 'en-CA' \| 'fr-CA' }`, persisted as `urlLang` only |

## Relationships

- Todo.categorySlug to Category.slug (many-to-one, soft reference, orphans tolerated)
- Todo.prioritySlug to Priority.slug (many-to-one, soft reference; unknown shows Medium)
- Page.emptyState to EmptyState (zero or one)

## Validation rules (single source)

Validation is enforced in the form (client) and again in the mock backend (400 with codes). Messages are
UI Labels keyed `validation.<field>.<code>`: `validation.title.required`, `validation.title.tooLong`,
`validation.description.tooLong`, `validation.dueDate.invalid`.

## Sorting rules

- By due date: ascending; tasks without a due date sort last.
- By priority: Priority.level descending (high first); ties broken by due date.
- By created date: newest first by default; direction can be reversed.
- Category and priority lists in dropdowns: `sortOrder` / `level`.
